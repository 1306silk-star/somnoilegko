# Панель управления «Сомной_легко»

Панель встроена в существующий сайт и живёт по адресу `/admin`. Стек не менялся:
HTML, CSS и обычный JavaScript без сборки. Сервер написан на стандартной библиотеке
Python — без установки зависимостей.

## Быстрый старт

1. Двойной клик по `start-admin.cmd` (Windows) или `python server/app.py`.
2. Откроется `http://localhost:8787/admin`.
3. Первый вход: **admin / somnoilegko**. Сразу смените пароль в разделе «Настройки» —
   до смены панель показывает предупреждение на каждой странице.

Сайт при этом доступен по `http://localhost:8787/` — это тот же самый `index.html`,
никаких копий проекта не создаётся.

## Два режима работы

Панель сама определяет, есть ли сервер, и подстраивается.

| | Серверный режим | Локальный режим |
|---|---|---|
| Когда включается | запущен `server/app.py` | панель открыта как файл или на GitHub Pages |
| Где живут данные | `server/data/*.json` | `localStorage` браузера |
| Сессия | HttpOnly-кука, недоступная из JS | токен в `localStorage`/`sessionStorage` |
| Публикация | сервер перезаписывает `data/content.js` | файл выгружается кнопкой в «Настройках» |
| Telegram | отправка через сервер, токен не покидает машину | отправка напрямую из браузера |
| Отложенные посты | фоновый планировщик сервера | пока открыта вкладка панели |

Локальный режим нужен, чтобы панель оставалась работоспособной на статическом
хостинге. Для постоянной работы рекомендуется серверный.

## Как правки попадают на сайт

```
Редактирование  →  Черновик  →  Публикация  →  data/content.js  →  сайт
```

- **Черновик** сохраняется автоматически и виден только в панели.
- **Предпросмотр** (`index.html?cms-preview=1`) показывает черновик — посетители его не видят.
- **Публикация** переносит черновик в опубликованную версию и переписывает
  `data/content.js`. Сайт подхватывает файл при следующей загрузке.

Скрипт `js/content-sync.js` подставляет контент в разметку по атрибутам
`data-cms` (одно поле) и `data-cms-list` (список). Разметка `index.html` сохранена
полностью: добавлены только атрибуты, ни один блок не переписан.

Если сервер не используется, в «Настройках» есть кнопка «Скачать data/content.js» —
файл кладётся в репозиторий вместо старого, и GitHub Pages обновляет сайт.

## Разделы

- **Обзор** — состояние сайта, метрики, ближайшие публикации, быстрые действия.
- **Главная страница** — первый экран, шапка, направления, задачи, маршруты, подход,
  «Обо мне», планы, футер. Вкладки соответствуют секциям сайта.
- **Проекты**, **Кейсы**, **FAQ**, **Отзывы** — списки с созданием, редактированием,
  копированием, сортировкой, удалением и статусом «черновик / опубликовано».
  Секция отзывов скрыта на сайте, пока нет ни одного опубликованного отзыва.
- **Контакты** — бренд, ссылки, финальный призыв, тексты модального окна.
- **SEO** — заголовок, описание, Open Graph и Twitter с счётчиками длины
  и превью поисковой выдачи. Пустые поля соцсетей наследуют основной заголовок.
- **Telegram** — создание постов, черновики, отложенная публикация, библиотека
  с фильтрами, предпросмотр сообщения, настройки бота.
- **Brand OS** — документы бренда: тон голоса, обещание, визуальный язык.
  Поиск, закрепление, копирование текста.
- **AI** — инструменты как шаблоны запросов с подстановками `{{...}}`.
  Работают без ключей (ручной режим) и с OpenAI-совместимым API.
- **Приложения** — внешние сервисы экосистемы. Первым подключено
  `https://time.somnoilegko.ru`: панель хранит только ссылку и открывает
  приложение в изолированном окне, не дублируя его функциональность.
- **Настройки** — смена логина и пароля, режим работы, выгрузка контента,
  откат черновика и возврат к исходному контенту.

## Подключение Telegram

1. Получите токен у [@BotFather](https://t.me/BotFather).
2. Добавьте бота администратором канала.
3. Впишите токен и канал:
   - серверный режим — `server/config.json` → `telegram.botToken` и `telegram.chatId`
     (шаблон лежит в `server/config.example.json`);
   - локальный режим — раздел «Telegram» → «Настройки».
4. Нажмите «Проверить подключение».

Пока токена нет, раздел полностью работоспособен: посты создаются, сохраняются
и планируются, а при попытке отправки панель прямо говорит, чего не хватает.

Токен в серверном режиме хранится только в `server/config.json`, который исключён
из git. В браузер он не передаётся.

## Безопасность

- Пароль хранится как PBKDF2-HMAC-SHA256, 210 000 итераций, со случайной солью.
- Серверная сессия — в HttpOnly-куке с `SameSite=Strict`; из JavaScript не читается.
- Пять неудачных попыток входа блокируют адрес на минуту.
- Сессия завершается после бездействия.
- Любой запрос к `/api`, кроме входа, требует активной сессии.
- Панель закрыта от индексации через `robots`.
- Внешние приложения открываются в `iframe` с `sandbox` и `referrerpolicy=no-referrer`.

## Структура файлов

```
admin/
  index.html              экраны входа и рабочей области
  css/                    оформление панели
  js/core/                крипто, схема данных, API, хранилище, авторизация, UI, поля, роутер
  js/views/               разделы панели
  js/app.js               запуск и оболочка
data/content.js           контент сайта — источник правды для страницы
js/content-sync.js        подстановка контента в разметку
server/app.py             сервер: статика, API, сессии, Telegram, планировщик
server/config.example.json  шаблон конфигурации
tools/qa/                 автоматические проверки панели и сайта
```

## Проверки

```
python tools/qa/run_checks.py     маршруты, формы, адаптивность, консоль, регресс сайта
python tools/qa/run_flows.py      черновики, предпросмотр, CRUD, SEO, Telegram, AI, пароль
python tools/qa/cleanup.py        уборка тестовых записей из рабочих данных
python tools/qa/restore_order.py  возврат порядка и статусов списков к исходным
```

Проверки нажимают кнопки по-настоящему, поэтому после прогона запускайте
`cleanup.py` и `restore_order.py` — они убирают следы и восстанавливают контент.

Проверки поднимают Chrome в фоновом режиме и работают через DevTools Protocol.
Перед запуском должен быть поднят `server/app.py`. Скриншоты складываются
в `tools/qa/screenshots`.
