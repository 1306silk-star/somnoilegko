# Запуск сайта и панели на домене

Панель управления умеет работать в полном объёме только вместе со своей
серверной частью: она проверяет пароль, хранит данные и перезаписывает
`data/content.js` при публикации. GitHub Pages раздаёт готовые файлы и не
выполняет код, поэтому там панель остаётся инструментом черновиков.

Здесь лежит всё, чтобы поднять проект на обычном сервере с Ubuntu (например,
VPS в Timeweb). Схема простая и стандартная:

```
Интернет → nginx (80/443, HTTPS) → приложение на 127.0.0.1:8787 → сайт, панель, API
```

## Один шаг

На сервере с Ubuntu выполните одну команду — она сделает всё остальное:

```bash
curl -fsSL https://raw.githubusercontent.com/1306silk-star/somnoilegko/main/deploy/install.sh \
  | sudo bash -s -- somnoilegko.ru
```

Скрипт установит python3, nginx и certbot, заберёт проект из GitHub, поднимет
его под systemd с автозапуском и перезапуском при сбое, выведет наружу через
nginx и получит сертификат Let's Encrypt. Если A-запись домена ещё не смотрит
на этот сервер, скрипт покажет нужный IP и подождёт до 15 минут, пока DNS
обновится, а затем сам выпустит сертификат.

После установки:

- сайт — `https://somnoilegko.ru/`
- панель — `https://somnoilegko.ru/admin`
- первый вход — `admin` / `somnoilegko`, смените пароль в «Настройках»

## Что где лежит

| | Путь |
|---|---|
| Код проекта | `/opt/somnoilegko` |
| Настройки, пароль, токен Telegram | `/etc/somnoilegko/config.json` |
| Данные панели | `/var/lib/somnoilegko/data` |
| Контент сайта | `/opt/somnoilegko/data/content.js` |
| Журнал | `journalctl -u somnoilegko -f` |

Настройки и данные лежат вне папки проекта, поэтому обновление кода их не
затрагивает. Пароль администратора хранится как PBKDF2-хеш в `config.json`
с правами `600`.

## Обновление кода

```bash
sudo bash /opt/somnoilegko/deploy/update.sh
```

Скрипт забирает свежую версию из GitHub, сохраняя опубликованный контент,
и перезапускает сервис.

## Полезные команды

```bash
systemctl status somnoilegko      состояние
systemctl restart somnoilegko     перезапуск
journalctl -u somnoilegko -f      журнал
nginx -t && systemctl reload nginx   проверить и применить конфигурацию nginx
```

## Как это проверялось

Топология «прокси → приложение» проверяется прогоном
`python tools/qa/run_proxy.py`: вход через прокси, сессионная кука с признаками
`Secure`, `HttpOnly` и `SameSite=Strict`, все разделы панели, публикация с
мгновенным появлением правки на сайте, сохранение сессии и выход.

Файлы `nginx.conf` и `somnoilegko.service` — шаблоны: `install.sh` подставляет
в них домен, порт и пути.
